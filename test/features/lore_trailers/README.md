# Lore trailer acceptance features

Executable contracts for hook-generated bylines and Lore IDs, trailer-block
placement, and the `LORE:` output of `sf start` and `sf show`. Commit rules
live in the [workflow article](../../../swarmforge/constitution/articles/workflow.md#lore-trailers);
output semantics live in the [handoff protocol](../../../swarmforge/handoff-protocol.md#lore-lines).

Run `bash test/acceptance.sh` from the repository root. The
[step handlers](../../acceptance/src/acceptance/steps.clj) use real Git and
`sf` in scratch repositories. Commits use the hook unless a step explicitly
skips it; fixture bypasses test detection and are not normal role workflow.

| Placeholder | Meaning |
|---|---|
| `\n` | Newline; a following leading space folds a trailer value. |
| `ID` | Task ID returned by `sf new`. |
| `LID` | Lore ID of the commit under test. |
| `C1`, `C2`, `C3` | Abbreviated SHAs of named fixture commits. |
| `L1`, `L3` | Hook-generated Lore IDs for those commits. |

Message comparisons omit trailing newlines. A check of the final `LORE:`
lines also requires that no other `LORE:` line appears.
