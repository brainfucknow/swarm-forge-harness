# QA: preserve project agents during adapter generation

Acceptance contract: [adapters](../features/adapters/adapters.feature).
Use real Bash, Git and Babashka, this task's `sf` and `install.sh`, and
scratch repositories under the task worktree's ignored `tmp/qa/adapters/`.
Set each scratch repository's author and committer to Codex. Invoke public
commands only; do not call production namespaces from QA scripts.

## Fixtures and scope

`sf adapters` runs in a normal scratch Git repository holding `swarmforge/`
and valid configuration. `install.sh` means `bash "$WT/install.sh" "$P"`,
where `WT` is this task's worktree and `P` is the scratch target. Use ordinary
`.git` directories: linked-worktree installation is outside this fix.

An unrelated agent is project-owned and has never been generated by
SwarmForge, regardless of its extension. Treat its contents as opaque bytes.
A managed adapter was generated by SwarmForge; changing its role to `session`
must remove its adapter, and changing its tier must update the public model
metadata. Do not pin generated prompt bodies with string assertions.

For collision fixtures, initially configure only `coder` as a subagent and
the other normal roles as session roles, then generate its managed adapters.
For a collision with `sf adapters`, introduce a valid new subagent role
`specialist` and its prompt, but precreate its adapter target as project-owned.
For installation, precreate the selected shipped `specifier` target in the
target project; the installer supplies its normal role catalogue. Other
generated adapters may already exist. Record byte snapshots of all existing
files and their paths in the three harness agent directories before running
the command. A collision must be diagnosed before any of those files change.
This does not require rolling back the installer's other project setup files.

## Checks

1. Execute every preservation example through each command. Compare the
   custom file's bytes before and after; verify configured subagent paths
   exist for Claude, Copilot and Codex. Repeat generation and installation
   to confirm preservation is not limited to the first run.
2. Generate the normal adapters, change `qa` to `session` and `coder` to
   `fast`, then regenerate. Confirm obsolete managed `qa` files disappear,
   `coder` model metadata follows `tiers.conf`, and a custom specialist file
   remains unchanged. A further run must leave the agent-directory snapshots
   identical. Existing committed generated adapters must continue to work.
3. Execute every collision example. Expect exit 1, a diagnostic naming the
   conflicting relative path, and identical before/after snapshots of all
   three agent directories. The command must neither overwrite the custom
   target nor partly regenerate other managed adapters.
4. Start with this task's base revision's shipped generated agent files and
   no local ownership/cache data. Regeneration must succeed and remain
   repeatable. Review the collision recognizer or ownership migration for
   accidental claims over unrelated files; compare behavior, not prompt text.
5. Run relevant existing sf unit and behavioral/acceptance suites, then
   inspect the task diff for unrelated policy or installer changes. Record
   actual passing checks and any untested cases separately in QA Lore.

Do not add audit policy, Speclj policy, worker-limit changes, automatic
upstream synchronization, or linked-worktree support to this task.
